# Dark Mode for Stripe Dashboard · by LunarCrush

A clean dark theme for `dashboard.stripe.com`. Stripe ships dark mode in its mobile apps and the Express Dashboard but not in the main web Dashboard. This extension adds it.

- One-click toggle from the toolbar, or `Alt+Shift+D`
- Intensity, brightness and contrast sliders; settings sync across the user's browsers
- Photos and avatars keep their true colors; charts keep their hues
- Never inverts when printing, so invoices and reports print light
- Runs only on `dashboard.stripe.com` and the Stripe frames embedded in it. Nothing is sent to LunarCrush or anyone else: no analytics, no network calls. Settings live in browser extension storage (and follow your browser sync, if you use it).

Made by [LunarCrush](https://lunarcrush.com). Not affiliated with or endorsed by Stripe, Inc.

## How it works
Luminance inversion with hue preservation (`invert(0.92) hue-rotate(180deg)`) on the document root, with photographic media re-inverted so it stays true to color. Its advantage over a hand-written palette: it survives Stripe Dashboard redesigns unchanged. Regions Stripe already renders dark (Workbench, code panels, dark modals) are detected by their real background color and re-inverted back to native.

The popup's **Copy report** button copies a diagnostics report (version, settings, the current route with every Stripe id masked, viewport, and a color tally of the page) to the clipboard for bug reports. It is user-initiated and nothing is transmitted.

## Repository layout
```
manifest.json     one manifest; build.sh derives the Chrome and Firefox variants
theme.css         the theme; tunables are CSS custom properties
content.js        applies settings at document_start, frame gating, native-dark detection, diagnostics
background.js     keyboard command, badge, default settings, dev hot-reload
popup/            toggle + sliders UI (LunarCrush design system, Plus Jakarta Sans bundled)
icons/            LunarCrush mark on the brand canvas, generated by store/tools/make_icons.py
store/            store listing copy, screenshots and promo tiles, the synthetic Dashboard mock, brand assets
tests/smoke.py    loads the built extension into Chromium and proves it themes the mock (CI runs this)
docs/RELEASE.md   how a version gets from a commit to the stores
build.sh          → dist/*.zip + SHA256SUMS
```

## Develop
1. Load unpacked: `brave://extensions` (or `chrome://extensions`) → **Developer mode** → **Load unpacked** → this folder. Firefox: `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on** → `manifest.json`.
2. On any Dashboard page, unpacked installs accept URL switches: `?sdm-dev=1` re-reads `theme.css` from disk on every refresh (no extension reload for CSS edits), `?sdm-reload=1` reloads the extension (after `content.js`, `background.js` or manifest edits), `?sdm-enabled=0|1` flips the theme. All inert in store builds.
3. Python tooling (icons, screenshots, smoke test) needs `pip install playwright pillow && playwright install chromium`.

```
bash build.sh                                  # packages
python3 tests/smoke.py --ext dist/build/chrome # proves the packaged Chrome build works
python3 store/tools/make_icons.py              # regenerate icons from popup/lc-mark.svg
python3 store/tools/capture.py                 # regenerate every store asset from the synthetic mock
```

## Release
See [docs/RELEASE.md](docs/RELEASE.md). Short version: bump `version` in `manifest.json`, add a CHANGELOG entry, tag `v<version>`, CI builds and attaches the zips to a GitHub Release, then upload to the Chrome Web Store developer console.
